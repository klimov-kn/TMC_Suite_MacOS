# Минимальный воспроизводитель ошибки блока FILE в PlanarRT_H 4.1 (macOS)

Два задания различаются ровно одной строкой в блоке 55:

| файл | строка блока 55 | результат в PlanarRT_H |
|---|---|---|
| `mini_ctl.TPL` | `RECT_STAT ABSORBER; 0; 10000; 0; 20000;` | `Step:1;Error:no` |
| `mini_file.TPL` | `FILE mini_file; 0; 10000; 0; 20000;` | `Step:1;Error : Missing separator ;` |

Всё остальное в файлах совпадает; `.eps` для `mini_file` не нужен — ошибка
возникает до открытия файла распределения (проверено: результат не меняется,
если файл удалить).

Причина — в самой программе, а не в задании. Диспетчер ключевых слов секции
`#TOPOLOGY` (`CTmcRTH_BlockList::ReadBlock`) для ветки `FILE`/`FILE_N`/`FILE_B`
сначала затирает буфер строки именем типа, а только потом разбирает строку:

```
FILE:                                RECT_STAT:
  CString::Format(m_line,"%s","FILE ")   ReadRectStat_1(err, param, 10)
  ReadFileStat_1(err, param, 5)          CString::Format(m_line,"%s","RECT_STAT ")
```

`ReadFileStat_1` копирует `m_line` (в котором теперь стоит литерал `"FILE "`),
отбрасывает первые 5 символов и ищет `;` в остатке — то есть в пустой строке.
`CTmcRTH_BlockList::Search_1Param` доходит до конца строки и выдаёт
`Missing separator ;`.

Адреса (arm64): диспетчер `0x100056db4`, ветка FILE `0x10005704c`
(`bl CString::Format` по `0x100057068` выполняется до
`b ReadFileStat_1` по `0x1000570e0`), ветка RECT_STAT `0x1000570e4`.
В срезе x86_64 то же самое: `0x10005f0e7` против `0x10005f183`.
Та же ошибка есть в `PlanarRT_X` (`0x10005b358` против `0x10005b3a8`).

---

## Исправлено

6 сентября 2026. Строка присвоения убрана из `ReadFileStat`, `ReadFileStatN` и
`ReadFileStatB`: теперь `ReadFileStat_1` разбирает настоящую строку задания, а
не литерал `"FILE "`. Правка внесена в `tools/import_win_src.py` (словарь
`PATCHES`), снимок `src/win_src` переимпортирован — разбор `ISSUES.md`, С-43,
и `DECISIONS.md`, M13.

Проверено сборкой для Linux (`planarrt_h_runcheck`, вывод поля отключён):

* `mini_file.TPL` — задание читается (`Error:no`); на счёте выводится
  `Can't open diel.data file {mini_file.eps}`, и это верно: файла распределения
  для этого образца нет, он для проверки разбора и не нужен;
* `hyper_sheath_0p4.TPL` — читается, распределение из `.eps` (1 057 041 узел)
  загружается, счёт идёт, созданы топология `.tt`, сигнал `.t` и поле `.ex`;
* контрольное `mini_ctl.TPL` и образец `demo_h.tpl` считаются как раньше.

Задания в этой папке остаются: они годятся как проверка на будущее.
